# Консилиум ИИ

Android-приложение для планшета (Kotlin + Jetpack Compose), которое отправляет
один запрос сразу нескольким LLM (Anthropic Claude, OpenAI GPT, Google Gemini,
DeepSeek, Mistral), а затем просит выбранную модель-арбитра свести все ответы
в один согласованный результат.

## Быстрый старт (если есть компьютер)

1. Откройте папку проекта в Android Studio (нужна версия с поддержкой
   Android Gradle Plugin 9.x — см. раздел про AGP 9 ниже).
2. Дайте Gradle синхронизироваться — все версии зависимостей собраны в
   `gradle/libs.versions.toml`.
3. Соберите и запустите на планшете или эмуляторе (`minSdk 26`).
4. В приложении: слева отметьте нужные модели галочками и вставьте их
   API-ключи, выберите модель-арбитра, справа введите запрос и нажмите
   «Спросить».

Готовых API-ключей в проекте нет и быть не может — их вводит пользователь
приложения на устройстве, они шифруются и остаются только там.

## Сборка APK без компьютера, только с планшета

В проекте уже лежит готовый workflow (`.github/workflows/build-debug-apk.yml`),
который собирает APK на серверах GitHub — планшету нужен только браузер.

1. **Заведите бесплатный аккаунт на github.com** (если его ещё нет) —
   прямо в браузере планшета.
2. **Создайте новый репозиторий** — кнопка "New" на главной странице
   GitHub. Сделайте его **Public** (для публичных репозиториев минуты
   сборки в GitHub Actions бесплатны без ограничений).
3. **Откройте Codespace на этом репозитории**: кнопка "Code" →
   вкладка "Codespaces" → "Create codespace on main". Откроется
   полноценная среда разработки (VS Code) прямо в браузере, с терминалом
   и файловым менеджером — это тоже бесплатно для нечастого использования.
4. **Загрузите архив с проектом** (`AIConsilium.zip`, который прислан
   в чате) в Codespace: в панели файлов слева правой кнопкой (или долгим
   тапом) → "Upload..." → выберите zip из "Загрузок" планшета.
5. **В терминале Codespace** (меню "Terminal → New Terminal") выполните:
   ```
   unzip AIConsilium.zip
   rm AIConsilium.zip
   ```
   Файлы распакуются прямо в корень репозитория (в архиве нет лишней
   вложенной папки).
6. **Отправьте код в репозиторий** — в панели "Source Control" (иконка
   с ветвящейся линией слева) нажмите "+" напротив изменённых файлов,
   затем "Commit" (потребуется ввести любое сообщение, например
   "initial commit"), затем "Sync Changes"/"Push".
7. Как только код окажется в репозитории, workflow запустится
   автоматически. Откройте вкладку **Actions** репозитория, дождитесь
   зелёной галочки (сборка занимает пару минут), откройте последний run
   и в разделе **Artifacts** внизу страницы скачайте
   `ai-consilium-debug-apk` — это и есть готовый APK (в zip-обёртке).
8. На планшете распакуйте скачанный zip (файловый менеджер Android
   умеет это из коробки) и откройте получившийся `app-debug.apk` —
   Android предложит установить приложение. Если появится предупреждение
   об источниках вне Google Play, разрешите установку для этого файла —
   это обычное дело для APK не из магазина, а не признак проблемы.

Дальше при любых правках кода: меняете файлы прямо в Codespace (или через
веб-редактор GitHub — иконка карандаша у файла), коммитите — APK
пересобирается сам, без повторной ручной настройки.

## Архитектура

```
ui/main          — Compose-экран (MainScreen — адаптивный master-detail),
                    ControlPanel (левая панель), WorkArea (правая панель),
                    MainViewModel/MainUiState — состояние экрана.
domain           — ConsensusEngine: строит промпт для арбитра и вызывает его;
                    ConsiliumProgress — события хода одного "созыва".
data/repository  — ConsiliumRepository: параллельно опрашивает модели
                    (Kotlin Coroutines async/await) и отдаёт прогресс как Flow.
data/remote      — Retrofit-интерфейсы и DTO по одному на семейство API
                    (Anthropic; общий OpenAI-совместимый для OpenAI/DeepSeek/
                    Mistral; Gemini) + AiProviderClientFactory, которая
                    собирает готовый клиент из настроек провайдера.
data/local       — SecureSettingsStore (Jetpack DataStore) + KeystoreCipher
                    (AES-256-GCM поверх Android Keystore) для хранения
                    API-ключей на устройстве.
data/model       — AIProvider, ProviderConfig, ModelAnswer, ConsiliumResult.
```

Поток одного запроса:
`MainViewModel.submitPrompt()` → `ConsiliumRepository.runConsilium()` — на
каждую отмеченную модель запускается параллельная корутина (`async`), ответ
каждой модели уходит в UI сразу по готовности (`Flow`), не дожидаясь остальных;
когда получены все ответы (успешные или нет), `ConsensusEngine` формирует
промпт-синтез и отправляет его модели-арбитру; итог тоже уходит в UI как
отдельное событие.

## Важные решения, о которых стоит знать

**AGP 9 и "built-in Kotlin".** С Android Gradle Plugin 9.0 (январь 2026)
поддержка Kotlin встроена в сам AGP, поэтому здесь **не** подключается
отдельный плагин `org.jetbrains.kotlin.android` — с AGP 9+ это ломает сборку.
Компилятор Compose (`org.jetbrains.kotlin.plugin.compose`) и
kotlinx.serialization остаются отдельными плагинами, как и раньше, и оба
подключены. compileSdk выставлен в 37 — это минимум, который требует Compose
1.12 (Compose BOM `2026.08.00`).

**Хранение API-ключей.** В ТЗ как пример был назван
`EncryptedSharedPreferences` — начиная с `androidx.security:security-crypto`
1.1.0-alpha07 (апрель 2025) Google пометила его как deprecated (проблемы
производительности и надёжности ключей на части прошивок). Вместо этого здесь
Jetpack DataStore + собственное шифрование AES-256-GCM напрямую через
`AndroidKeyStore` (`KeystoreCipher.kt`) — тот же принцип "ключ не покидает
Keystore", без лишней зависимости от Tink.

**Имена моделей — редактируемые поля, а не константы.** Провайдеры
переименовывают/выводят из обращения модели регулярно (например, DeepSeek
24 июля 2026 полностью отключила `deepseek-chat`/`deepseek-reasoner` в пользу
`deepseek-v4-flash`/`deepseek-v4-pro`). Поле "Модель" в панели настроек
редактируется прямо в приложении для каждого провайдера, значение по
умолчанию — самое актуальное на момент написания:

| Провайдер | Модель по умолчанию   | Примечание                                  |
|-----------|------------------------|----------------------------------------------|
| Anthropic | `claude-opus-5`        | —                                              |
| OpenAI    | `gpt-6-astra`           | если недоступна на вашем аккаунте — `gpt-5.x` |
| Gemini    | `gemini-pro-latest`     | алиас Google, сам указывает на актуальную     |
| DeepSeek  | `deepseek-v4-flash`     | `-pro` — более мощный вариант                 |
| Mistral   | `mistral-large-latest`  | алиас Mistral                                  |

**OpenAI, DeepSeek и Mistral — один клиент.** Все трое используют одинаковую
схему Chat Completions (`{"model","messages"} → {"choices":[{"message"}]}`),
поэтому `OpenAiCompatibleApi`/`OpenAiCompatibleProviderClient` один на всех —
отличаются только base URL, заданные в `AiProviderClientFactory`. У самого
OpenAI это исторический, но ещё долго поддерживаемый эндпоинт (новый
`/v1/responses` не совместим с DeepSeek/Mistral, поэтому здесь не используется).

**Два уровня тайм-аута.** Сетевой (OkHttp `readTimeout`, 90 сек — ловит
зависшее соединение) и прикладной (`withTimeoutOrNull` в репозитории,
60 сек — даёт предсказуемое и дружелюбное сообщение вместо сырой ошибки
сокета). Ошибка одной модели не отменяет остальные и не мешает синтезу — если
хотя бы одна модель ответила успешно, арбитр работает с тем, что есть.

## Что стоит сделать перед реальным использованием

- **Иконка приложения** — сейчас это простая заглушка (латунный круг на
  тёмном фоне). Перегенерируйте через Android Studio → New → Image Asset,
  если нужен полноценный арт.
- **Версии зависимостей** в `gradle/libs.versions.toml` актуальны на момент
  написания (сентябрь 2026) — Android Studio подскажет более новые патч-версии
  при синхронизации, если они выйдут позже.
- **Логирование сети** (`NetworkModule.okHttpClient`) сейчас на уровне BASIC;
  для отладки можно временно поднять до BODY, но учтите, что тогда в logcat
  целиком попадут промпты пользователя и ответы моделей.
- Это не готовое к публикации приложение "под ключ" — например, здесь нет
  экрана истории с сохранением между запусками (история живёт только в
  памяти ViewModel на время сессии) и нет тестов. Архитектура (Repository +
  ViewModel с чистым UI State) рассчитана на то, чтобы то и другое было
  несложно добавить отдельно.
